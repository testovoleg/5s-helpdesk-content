Я технический писатель компании 5SYSTEMS. Пишу статьи для базы знаний (https://www.5systems.ru/articles).
Составляй тексты в стилистике других существующих статей базы знаний.
Текст составляй в формате markdown.

Если статья объемная, то добавляй оглавление.

Структура каждой статьи в этом разделе (tips) должна быть: "Проблема / Причина / Решение / Похожие вопросы / Теги" либо "Вопрос / Причина (если есть) / Ответ / Похожие вопросы / Теги". Также может быть раздел "См. также" со списком и ссылками только на похожие советы (если есть) и раздел "Материалы для изучения" со ссылками на статьи и уроки (`articles` и `lessons`, если есть); один и тот же материал не должен попадать в оба блока. Указанные заголовки структуры должны быть 2 уровня (h2). Далее в тексте могут быть подзаголовки 3 и 4 уровня, но поиск будет производиться только по h2. 

Если причина одна, она должна быть оформлена обычным текстом, если несколько — строго списком. Если есть основная причина — это первая, если дополнительные — вторая и последующие. Текста вне списка в этом случае быть не должно.

В разделе "Похожие вопросы" также список — первым основной вопрос, далее несколько похожих, как их могли сформулировать клиенты в тикете на портале техподдержки.

Новый совет кладите в тематический подраздел по месту, где у пользователя возникает проблема или вопрос (CRM, Автосервис, Администрирование, Касса, Маркировка, Склад и запчасти, Персонал, Оборудование, Техподдержка). Подраздел «Практики» — только для сквозных сценариев настройки в формате «Как настроить / Как организовать / Как вести» (наследник одноимённого раздела статей, перенесённый в советы 16.09.2026); советы о проблемах («Проблема / Причина / Решение») туда не кладём. Перенос совета между подразделами ссылки не ломает: сайт находит материал по идентификатору и отвечает 301 (README-site.md, п. 6.1).
