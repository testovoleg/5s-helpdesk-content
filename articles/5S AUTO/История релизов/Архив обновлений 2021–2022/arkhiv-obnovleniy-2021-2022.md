## Июнь 2022

### 🏦 Удобная загрузка и разнесение банковской выписки

> 🛠 Комментарий для черновика: *Источник: https://www.5systems.ru/news/udobnaya-zagruzka-i-raznesenie-bankovskoy-vypiski*

Реализован функционал ***загрузки банковской выписки*** из файла, предварительно полученного из банка.

<small>*Опубликовано 12.10.2026: [https://kb.5systems.ru/articles/5s-auto/istoriya-relizov/arkhiv-obnovleniy-2021-2022](https://kb.5systems.ru/articles/5s-auto/istoriya-relizov/arkhiv-obnovleniy-2021-2022)*</small>

> *Актуально начиная с версии релиза 5S AUTO **2.002.007**.*

Обработка “Загрузка выписки” вызывается из реестра документов. В окне обработки требуется выбрать *организацию*, *расчетный счет* и загрузить *файл импорта*. Выписка заполняется платежами по выбранным организации и счету.

При выделении в выписке строки с определенным платежом в поле “Сделки контрагента” отображаются документы по данному контрагенту, программа подсвечивает документ, который может выступать в качестве сделки по строке платежа.

В колонке “Загружать” производится отметка флажками платежей, которые требуется разнести.

Возможен выбор одного из трех режимов загрузки: Автоматически с разбивкой по дням, Загрузить в существующую или Создать новую.

При нажатии на кнопку “Загрузить выписку” в зависимости от выбранного режима будет создана и проведена банковская выписка – одна или несколько.

> 📚 *Подробнее см. статью на Базе знаний: [Обработка для загрузки банковских выписок](../../Банки%20и%20платежные%20системы/Банковские%20выписки/Обработка%20для%20загрузки%20банковских%20выписок/obrabotka-dlya-zagruzki-bankovskikh-vypisok.md)*

### 🔔 Уведомление о создании сделки без ответственного

> 🛠 Комментарий для черновика: *Источник: https://www.5systems.ru/news/uvedomlenie-o-sozdanii-sdelki-bez-otvetstvennogo*

Добавлен новый тип уведомления "Создана сделка без ответственного".

Данное уведомление создается при создании сделки и адресуется всем пользователям с должностью из настройки воронки в подразделении сделки.

1. Необходимо выполнять регистрацию уведомления "ПриЗаписи" бизнес-процесса. При повторных записях необходимо удалять старые регистрации: если ответственный не заполнен, то необходимо снова регистрировать событие с учетом подразделения.
2. Адресация: направлять уведомление на должности, указанные в таблице адресации уведомления, подразделение сделки должно соответствовать подразделениям пользователей, указанных в регистре сведений "Сведения адресации".
3. Добавлено начальное заполнение элемента уведомления в макеты. Уведомление направляется на оператора кол-центра и включено по умолчанию.

### 🏷️ Оптимизированы алгоритмы канбана

> 🛠 Комментарий для черновика: *Источник: https://www.5systems.ru/news/optimizirovany-algoritmy-kanbana*

Оптимизированы алгоритмы канбана при выводе всех завершенных сделок с целью исключения подвисания системы.

1. Ограничен период повторного вывода – не ранее 30 секунд. Исключение изменение отбора.
2. При изменении отбора не сохраняется ранее установленный порядок процессов на канбане.
3. Изменен период вывода сделок по умолчанию: вместо 1 года - последние три месяца.
4. При выводе более 3000 сделок на канбан автоматически включается режим "ограниченной функциональности":<br>
   \- не поддерживается расчет последней активности;<br>
   \- контекстной подсказки;<br>
   \- список назначенных дел.
5. Режим автоматически отключается при отборе на канбане меньшего количества сделок.

- Сделана привязка фотографии восстановленного агрегата к характеристике.
- В отображение номерных агрегатов в прайс листах добавлен вывод параметра "Качество".
- Добавлена возможность создавать для диагностической анкеты штрихкод для идентификации с помощью сканера без входа в заказ-наряд.
- При идентификации сканером заказ-наряда открывается сам документ.
- При печати этикетки для восстановленного агрегата в печатной форме выводятся данные из характеристики: качество, дата изготовления.
- При сканировании штрихкода анкеты из АРМ "Рабочее место сотрудника цеха" устранена блокировка заказ-наряд на время заполнения анкеты.

  *Пояснение:* На АРМ сотрудника цеха при сканировании открывается Анкета. При этом блокировка заказ-наряда нужна только при ее записи. Если при записи не получается заблокировать заказ-наряд, то формируется Уведомление с просьбой закрыть заказ-наряд сотруднику, у которого он открыт. Уведомление будет формироваться при каждой неудачной попытке записи анкеты. При неудачной попытке форма остается открытой. В режим авторизации АРМ также не переходит. Можно закрыть анкету без сохранения.
- Добавлен новый предопределенный тип уведомления "Закройте форму документа".
- Добавлена проверка заполнения качества для характеристик агрегатов внутреннего агрегатного ремонта при переводе заказ-наряда в состояние "Выполнен" (для вида ремонта с признаком "Ремонт собственных агрегатов", при учете по характеристикам).
- Добавлено создание складских ордеров для документов "Комплектация" и "Разукомплектация".

### 📋 Добавлена хоз. операция «Сводный акт»

> 🛠 Комментарий для черновика: *Источник: https://www.5systems.ru/news/dobavlena-khoz-operaciya-svodnyy-akt*

Добавлена хоз. операция "**Сводный акт**" для документа "Реализация товаров" для упрощения работы с корпоратиными клиентами. Теперь клиенту по итогу периода можно создать один сводный акт и включить в него все заказ-наряды и реализации.

Как это работает:

1. Добавлены реквизиты начала и окончания периода документа *_5с_НачалоПериода, _5с_КонецПериода*. На форме документа добавлена возможность редактирования периода для данной хозяйственной операции.
2. Добавлен реквизит табличной части "Товары" *ДокументОснование*, который заполняется заказ-нарядом.
3. Добавлена возможность заполнения табличной части заказ-нарядами за выбранный период по Контрагенту и подразделению в состоянии "Закрыт".
4. В конфигурацию добавлены обработки для печатных форм: "Сводный акт" и печати заказ-нарядов по акту (любая форма заказ-наряда по выбору).
5. При проведении закрывается дебиторская задолженность по заказ-нарядам, заказ-нарядам устанавливается признак "не РУ" (при записи). Формируется дебиторская задолженность по Сводному акту. Для корректной работы рекомендуется вести учет задолженности по отдельным договорам для заказ-нарядам и сводным актам. Всю оплату от контрагента проводить по договору Сводного акта.
6. При проведении двигаются границы по всем договорам заказ-нарядов и договору Сводного акта.

> 📚 *Подробнее см. статью на Базе знаний: [Сводный акт](../../Автосервис/Сводный%20акт/svodnyy-akt.md)*
