# Требования к сайту базы знаний

Что сайт (kb.5systems.ru) должен уметь сверх обычного рендера markdown, чтобы правильно показывать этот репозиторий. Источник данных для всего, что не текст статьи, — `index.json` в корне: он пересобирается при каждом коммите скриптом `.scripts/generate-index.py`, читать файлы `.order` напрямую не требуется. Общее устройство репозитория описано в [README.md](README.md).

## 1. Статьи и подразделы в чужих разделах

### Зачем

На старом сайте одна и та же статья часто числилась в нескольких разделах: «Подключение сканера штрихкодов» лежит в «Торговом оборудовании» и одновременно показывается в подразделе «Штрихкодирование номенклатуры» раздела «Склад и запчасти». Разделы продуктов (5S Chat, 5S Cloud, 5S TSD, 5S Pay, 5S LINK) своих статей не имеют вовсе: это подборки ссылок на статьи 5S AUTO.

Копировать файлы нельзя: копия разошлась бы с оригиналом при первой же правке. Поэтому каждая статья хранится ровно в одной папке, а в чужой раздел попадает ссылкой в `.order`. Задача сайта: показать её в списке чужого раздела на нужной позиции, ведя на её единственную страницу.

### Как устроен `.order`

Файл лежит в папке раздела и перечисляет содержимое по одной строке:

| Строка | Что означает |
| --- | --- |
| `Подключение кассы ККМ` | Своя статья или свой подраздел: папка с таким именем лежит рядом |
| `../Маркировка/Интеграция с ТС ПИоТ` | Заимствование: строка со слэшем, путь относительно папки `.order`. Цель — статья или целый подраздел, в том числе из другого корня (`../../../tips/…`) |
| `-Обзор интерфейса Онлайн-каталога` | Скрытая статья: дефис без пробела. Страница есть, в списке раздела её нет |
| `# …` | Комментарий |

Позиция строки — порядок показа. Статьи и подразделы в одном списке перемешаны, и это существенно: подраздел «Интеграция с ТС ПИоТ» стоит между статьями «Рабочие места» и «Настройка приложения 5S Pay», как на старом сайте. Папки, не упомянутые в `.order`, идут после списка по алфавиту.

### Что лежит в `index.json`

Дерево разделов `sections`, для каждого корня (`articles`, `tips`, `lessons`):

```json
{
  "name": "Торговое оборудование",
  "path": "articles/5S AUTO/Торговое оборудование",
  "order": 24,
  "sections": [
    { "name": "Интеграция с ТС ПИоТ", "path": "articles/5S AUTO/Маркировка/Интеграция с ТС ПИоТ", "order": 3, "borrowed": true },
    { "name": "Настройка терминалов Сбербанка", "path": "articles/5S AUTO/Торговое оборудование/Настройка терминалов Сбербанка", "order": 7 }
  ]
}
```

| Поле узла | Смысл |
| --- | --- |
| `path` | Настоящая папка узла. У заимствованного она лежит вне родителя |
| `order` | Позиция в `.order` родителя, той же нумерацией, что у статей раздела |
| `borrowed` | `true`, если подраздел показан здесь ссылкой; содержимое берётся из его `path` |
| `sections` | Вложенные узлы, только у разделов с подразделами |

Список `materials`, все статьи:

```json
{
  "path": "articles/5S AUTO/Торговое оборудование/Подключение сканера штрихкодов",
  "title": "Подключение сканера штрихкодов",
  "type": "articles",
  "order": 5,
  "updated_at": "2026-02-05",
  "date_kind": "updated",
  "added_at": "2026-09-02T13:43:09+03:00",
  "reading_time": 8,
  "also_in": [
    { "path": "articles/5S AUTO/Склад и запчасти/Штрихкодирование номенклатуры", "order": 1 }
  ]
}
```

| Поле материала | Смысл |
| --- | --- |
| `path` | Папка статьи; физический раздел — `path` без последнего сегмента |
| `order` | Позиция в своём физическом разделе |
| `also_in` | Чужие разделы, где статью надо показать, с позицией в каждом; поля нет, если статья только у себя |
| `hidden` | `true`: в списки не выводить, страница доступна по прямой ссылке |
| `type` | Корень: `articles`, `tips` или `lessons`; заимствовать можно между корнями |

### Алгоритм списка раздела

Для раздела с путём `S` список собирается из трёх источников и сортируется по `order` по возрастанию. Нумерация общая, поэтому источники правильно перемешиваются.

1. Свои статьи: материалы, у которых `path` без последнего сегмента равен `S`, без `hidden`. Позиция — их `order`.
2. Заимствованные статьи: материалы, у которых в `also_in` есть элемент с `path == S`. Позиция — `order` из этого элемента, не собственный `order` статьи.
3. Подразделы: узлы `sections` дерева для `S`, свои и с `borrowed: true` одинаково. Позиция — `order` узла.

Узел с `borrowed: true` рендерится тем же алгоритмом по своему настоящему `path`. Разделы продуктов состоят только из заимствований, особой ветки для них не нужно.

### Адреса, хлебные крошки, поиск

- У статьи один адрес, он выводится из физического `path`. Из чужого раздела ведёт обычная ссылка на него; второй страницы с тем же текстом быть не должно.
- Хлебные крошки проще строить по физическому пути. Путь, по которому пришёл читатель, в данных отсутствует.
- Поиск и сортировка по дате работают по `materials`: каждая статья там один раз.
- Внутренние ссылки в тексте статей относительные и ведут на физические пути, заимствования на них не влияют.

### Примеры в репозитории

| Случай | Где смотреть |
| --- | --- |
| Статья в двух разделах | «Подключение сканера штрихкодов»: лежит в «Торговом оборудовании», через `also_in` показана в «Склад и запчасти / Штрихкодирование номенклатуры» |
| Статья в трёх разделах | «Настройка шаблонов WhatsApp Business API»: лежит в «Сообщения / WhatsApp», `also_in` ведёт в CRM и «Сообщения» |
| Заимствованный подраздел | «Интеграция с ТС ПИоТ» из «Маркировки» показан в «Торговом оборудовании» узлом с `borrowed: true` |
| Раздел продукта из одних ссылок | `articles/5S Chat` и подразделы по мессенджерам; `articles/5S LINK` показывает целый раздел «Приложение 5S LINK» из 5S AUTO |
| Заимствование между корнями | строка `../../../tips/…` в `.order` статей: у материала `type: "tips"`, в `also_in` путь раздела из `articles` |

Если генератор не находит цель заимствования, он печатает предупреждение `.order: не найден материал …` и пропускает строку; сайту стоит терпимо относиться к элементу `also_in`, чей раздел не найден в дереве.

## 2. Ссылки на разделы

Ссылки из статей на файлы других статей (`…/file.md`, с якорем или без) сайт переводит в свои адреса. Ссылки на папки разделов, то есть относительные пути со слэшем на конце, должны вести на страницы разделов. В репозитории их 53 в 32 материалах, и они появляются закономерно: страницы-списки старого сайта стали подразделами, ссылка на такую страницу превращается в ссылку на папку подраздела; ссылки на корневые папки «База знаний» и «Уроки» тоже штатные.

```markdown
проверьте, нет ли готового ответа в [Базе знаний](../../../) или в [Уроках](../../../../lessons/)
см. статьи в разделе «[Мобильное приложение 5S LINK v1](../Мобильное%20приложение%205S%20LINK%20v1/)»
```

Правило разрешения относительной ссылки:

1. Привести путь к абсолютному внутри репозитория, как для ссылок на `.md`.
2. Корневая папка `articles/`, `tips/`, `lessons/` — вести на соответствующий список (`/articles`, `/tips`, `/lessons`).
3. Путь совпадает с `path` узла дерева `sections` — вести на страницу раздела тем же маршрутом, что использует навигация.
4. Путь совпадает с `path` материала (папка статьи без имени файла) — вести на статью.
5. Всё остальное (картинки, вложения) — как есть.

Проверка: в «Как обратиться в техническую поддержку» ссылки «Базе знаний» и «Уроках» открывают списки статей и уроков; в отчёте «Регистрация внешних пользователей» ссылка «Мобильное приложение 5S LINK v1» открывает подраздел; ссылка `../` в любой статье открывает её раздел.

## 3. Видео и ссылки на YouTube

### Что уже правильно

Постер со ссылкой на mp4 — `[![подпись](attachments/video-….png)](https://edu.5systems.ru/….mp4)` — становится элементом `<video>` с нашим постером и кнопкой воспроизведения сайта. Так оформлены 128 роликов, менять ничего не нужно.

### Что нужно поправить

Сейчас любая ссылка на YouTube, где бы она ни стояла, заменяется плеером, а её текст исчезает. Из подписи

```markdown
**[Курс «Диагностические анкеты» — вебинар 5SYSTEMS 09.12.2020](https://www.youtube.com/watch?v=zdsD17fXSy0):**
```

получается `<p><strong><iframe …></iframe>:</strong></p>`: плеер, двоеточие, `<iframe>` внутри `<strong>`, а ниже второй плеер того же вебинара с mp4. В «Порядке работы с кассами ККМ» список из четырёх названий роликов стал четырьмя плеерами без названий, в «Передаче смен» плеер встаёт посреди фразы. Таких ссылок с текстом 13 в 11 статьях и ещё два постера, ведущих на YouTube.

Правило, как в обычных markdown-движках:

1. Голая ссылка отдельным абзацем (единственное содержимое абзаца, текст совпадает с адресом) — встроенный плеер.
2. Ссылка с текстом внутри абзаца, заголовка, пункта списка или выделения — обычная ссылка `<a href>` с этим текстом.
3. Постер со ссылкой на YouTube `[![…](poster.png)](https://youtu.be/…)` — либо плеер, либо картинка-ссылка, лишь бы одинаково везде.
4. `<iframe>` не вкладывать в строчные элементы: плеер заменяет весь абзац.

Проверка: в «Диагностических анкетах» видна подпись ссылкой на YouTube и один плеер с mp4 под ней; список «Видео по теме» в «Порядке работы с кассами ККМ» состоит из текстовых ссылок; абзац из одного адреса YouTube показывает плеер.

## 4. Раздел «Что нового»: заметки редакции и архив

Лента «Что нового» строится по датам из `index.json` (`added_at`, `updated_at`) и знает, что и когда менялось. Редакция добавляет два рукописных источника.

### Файл заметок

Путь: [`whats-new/Заметки редакции.md`](whats-new/Заметки%20редакции.md). Заголовки второго уровня — месяцы, под ними пункты списка, по одному на изменение:

```markdown
## Сентябрь 2026

- 10.09.2026 — [Как обратиться в техническую поддержку](../articles/5S%20AUTO/Прочее/…/kak-obratitsya-v-tekhnicheskuyu-podderzhku.md) — перенесена с сайта отдельной статьёй; совет с тем же названием остаётся.
- 09.09.2026 — [Настройка интеграции с ТС ПИоТ](../articles/…/nastroyka-integracii-s-ts-piot.md), [Установка ЕСМ](../articles/…/ustanovka-edinogo-servisnogo-modulya-esm.md) — три статьи объединены в подраздел.
- 07.2026 — Оптимизирована загрузка изображений в 30 статьях.
```

Грамматика строки:

```
- <дата> — <ссылки> — <текст>
- <дата> — <текст>

<дата>    ДД.ММ.ГГГГ (день) или ММ.ГГГГ (месяц)
<ссылки>  одна или несколько markdown-ссылок [Название](относительный путь) через запятую
<текст>   свободный markdown, может содержать ссылки на разделы статей (#якорь)
```

Разделитель — длинное тире с пробелами (« — »); внутри текста тире тоже встречается, поэтому разбираются только первые два разделителя. Всё до первого заголовка месяца — вводный текст, в ленту не идёт. Материал по ссылке — путь без имени файла `*.md`, он совпадает с `path` материала в `index.json`.

Как показывать:

1. Если у материала из ссылки в том же месяце есть автоматическая запись, текст заметки выводится под ней; ярлык записи («Перенесена», «Дополнена») остаётся.
2. Если пары нет, заметка выводится отдельной строкой в своём дне (при полной дате) или в конце месяца (при дате «ММ.ГГГГ»), с названием статьи ссылкой.
3. Несколько ссылок в строке — одна заметка, прикреплённая к каждой записи; без записей — одна отдельная строка со всеми ссылками.

### Архив старой базы

Перенесённая страница «Последние добавленные статьи» старого сайта (51 месяц, июнь 2022 — август 2026) лежит обычной статьёй в разделе «Полезное»: [`articles/5S AUTO/Полезное/Последние добавленные статьи/`](articles/5S%20AUTO/Полезное/Последние%20добавленные%20статьи/poslednie-dobavlennye-stati.md). Она попадает в `index.json` как материал, отдельно рендерить её не нужно. Просим дать на неё ссылку внизу ленты «Что нового», например «Архив изменений старой базы (2022–2026)».

Папка `whats-new/` в корни материалов не входит и в `index.json` не попадает: в ней только файл заметок. Ссылки в нём проверяются вместе со статьями.
